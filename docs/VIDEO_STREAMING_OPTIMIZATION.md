# MiniNAS 동영상 무손실(원본 화질 유지) 스트리밍 버퍼링 최적화 검토 보고서

**작성 일자**: 2026-11-16  
**대상 시스템**: MiniNAS (Go 백엔드 + React 프론트엔드)  
**핵심 요구사항**: 원본 화질을 유지하면서 네트워크 상태에 따른 동영상 버퍼링 개선

---

## 1. 현황 및 문제 원인 분석

### 1.1 스트리밍 아키텍처
* **백엔드**: `/api/files/stream` 엔드포인트에서 Go의 `http.ServeContent`를 사용하여 HTTP Range Request(206 Partial Content)를 직접 서빙합니다.
* **프론트엔드**: `MediaViewer.tsx`에서 HTML5 `<video src="/api/files/stream?..." controls>` 엘리먼트로 직접 재생합니다.

### 1.2 네트워크 환경에 따른 멈춤 발생 원인
1. **원본 비트레이트 직송출**: 고화질 영상(1080p, 4K)은 초당 전송량(10Mbps~50Mbps 이상)이 큽니다. 대역폭이 비트레이트 밑으로 떨어지면 버퍼 고갈이 발생합니다.
2. **브라우저의 소극적 기본 버퍼 정책**: 크롬 및 사파리 브라우저는 메모리와 데이터 절약을 위해 전방 3~10초 분량만 최소한으로 선행 다운로드합니다.
3. **버퍼 채터링 (Buffer Chattering)**: 버퍼 고갈 후 0.5초치만 채워져도 즉시 재생을 시도합니다. 이로 인해 멈춤과 재생이 반복됩니다.
4. **일시정지(Pause) 시 다운로드 중단**: 브라우저는 일시정지 상태에서 다운로드 연결을 중단하거나 대역폭을 최소화합니다.

## 2. 핵심 엔지니어링 개념: 버퍼링의 역설

> 속도가 느리면 많이 쌓고, 속도가 빠르면 적게 쌓아야 하는가?

사용자의 직관적 기대와 실제 시스템 물리 한계 사이에는 차이가 존재합니다:

| 구분 | 느린 네트워크 (유입 속도 저하) | 빠른 네트워크 (충분한 대역폭) |
| :--- | :--- | :--- |
| **사용자의 기대** | 끊길 위험이 높으므로 5분~10분 분량을 미리 받아두기를 원함 | 실시간으로 잘 들어오므로 조금만 받아도 충분하다고 여김 |
| **실제 물리적 한계** | • 소비 속도(재생)가 유입 속도보다 빠름<br>• 5분치를 모으려면 수 분 이상 로딩 스핀만 대기해야 함<br>• 재생 시작 시 버퍼를 물리적으로 많이 쌓을 수 없음 | • 5분치 버퍼를 단 수 초 만에 채울 수 있음<br>• 한 번 가득 채워두면 네트워크 단절 시에도 무중단 재생 보장 |
| **엔지니어링 전략** | • **최소 안전 버퍼(4초)** 확보 시 즉시 재생 시작<br>• 필요 시 사용자가 **원클릭 선행 충전**을 실행할 수 있도록 지원 | • **적극적 선행 버퍼 확장(30~60초)**으로 여유 대역폭 완전 활용<br>• 브라우저 탭 메모리 보호 |

## 3. 화질 무손실 최적화 솔루션 4단계

### 솔루션 1: 적극적 선행 다운로드 (`preload="auto"`)
* **내용**: 브라우저의 비디오 프리로드 속성을 `auto`로 명시합니다.
* **효과**: 브라우저가 유휴 대역폭을 활용하여 30초~60초 이상의 안전 버퍼를 선제 적재합니다.

### 솔루션 2: 타임라인 버퍼 캐시 게이지 시각화
* **내용**: 플레이어 타임라인 하단에 현재 확보된 버퍼 초수와 상태 배지(쾌적, 안전, 부족)를 실시간 렌더링합니다.
* **효과**: 사용자가 현재 네트워크 안전 마진을 직관적으로 파악할 수 있습니다.

### 솔루션 3: 스마트 재생 재개 임계값 (Anti-Chattering)
* **내용**: 버퍼 고갈(`waiting`, `stalled`) 발생 시 최소 **4초 분량의 안전 버퍼가 확보될 때까지 대기 후 자동으로 재생을 재개**합니다.
* **효과**: 0.5초 재생 후 다시 멈추는 채터링 현상을 완전히 차단합니다.

### 솔루션 4: 무손실 FastStart 메타데이터 최적화
* **내용**: MP4 컨테이너의 인덱스 메타데이터(`moov atom`)를 파일 선두로 이동합니다 (`-c copy -movflags +faststart`).
* **효과**: 재인코딩이 없으므로 화질 손실이 전혀 없습니다. 첫 프레임 재생 시작 지연을 4~6배 단축합니다.

## 4. Seek(구간 이동) 시의 동작 및 안정성

1. **버퍼 내 구간 탐색 (Buffer Hit)**
   * 이미 선행 다운로드된 버퍼 범위 내로 이동할 경우 네트워크 요청 없이 즉시 재생(0.0초 지연)합니다.
2. **버퍼 외 원거리 점프 (Buffer Miss)**
   * 기존 진행 중인 다운로드를 중단(Abort)합니다.
   * 새 위치의 HTTP Range 요청(`Range: bytes=xxx-`)을 발송하여 새 위치부터 즉각 버퍼링을 시작합니다.
   * `FastStart`가 적용된 파일은 메타데이터가 선두에 있어 바이트 오프셋을 즉시 계산합니다.
