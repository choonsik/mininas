**테스트 대상**: 고비트레이트 원본 영상 (1080p FHD 12Mbps / 4K UHD 35Mbps)  
**비교 대상**:
* **[기존 방식]**: 기본 HTML5 `<video src>` (브라우저 기본 소극적 버퍼링, FastStart 미적용, 채터링 방지 없음)
* **[개선 방식]**: MiniNAS 무손실 버퍼 최적화 (`preload="auto"`, 무손실 FastStart 헤더 이동, Anti-Chattering 4초 안전 버퍼, 실시간 HUD & 10초 부스터)

## 2. 네트워크 환경별 시나리오 벤치마크

### 시나리오 A: Wi-Fi 음영 지역 / 신호 간섭 발생 (순간 속도 3Mbps 이하로 급락)
* **기존 방식**:
  * 비디오가 멈추자마자 0.3초치 데이터가 들어오면 바로 재생 시도 → 0.5초 만에 다시 멈춤 → 또 0.3초 재생 후 멈춤...
  * 이른바 **"버퍼 채터링(Buffer Chattering)"**으로 인해 시청이 불가능한 수준의 스트레스 발생.
* **개선 방식**:
  * 버퍼 고갈 즉시 **Anti-Chattering 로직 작동**.
  * 화면에 반투명 HUD(`네트워크 안전 버퍼 충전 중... 현재 2.1s / 4.0s`) 표시.
  * 최소 4초치 안전 마진이 채워진 후에만 재생을 부드럽게 재개하여 끊김 반복 현상 차단.

### 시나리오 B: 모바일 LTE / 외부 원격 접속 (대역폭 변동 심함)
* **기존 방식**:
  * 영상을 틀어놓고 화장실을 다녀오거나 자리를 비워도 버퍼가 거의 차오르지 않아, 돌아와서 재생하면 금방 다시 멈춤.
* **개선 방식**:
  * 사용자가 **[⚡ 10초 안전 버퍼 충전]** 버튼을 클릭하면, 플레이어가 10초 분량의 든든한 버퍼를 집중 확보한 뒤 자동 재생.
  * 화질 손실 없이 네트워크 변동 구간을 무사히 통과.

### 시나리오 C: 가정 내 기가비트 LAN / 5GHz 고속 Wi-Fi
* **기존 방식**:
  * 네트워크가 아무리 빨라도 브라우저가 앞으로 5초치만 받아놓고 연결을 쉬고 있어, 순간적인 대용량 파일 복사 등으로 일시적 병목이 생기면 갑자기 멈춤.
* **개선 방식**:
  * 여유 대역폭을 활용해 앞서 30~60초 이상의 버퍼를 넉넉하게 적재해 두므로, 홈 네트워크에 일시적인 트래픽 피크가 와도 영상 재생에 전혀 영향을 주지 않음.

## 3. 브라우저 개발자 도구(DevTools)를 활용한 실전 검증 가이드

사용자가 직접 브라우저에서 이전/이후 차이를 재현 및 검증할 수 있는 방법입니다:

1. **개발자 도구 열기**: `F12` 또는 `Cmd + Option + I` (Chrome / Safari / Edge).
2. **네트워크 조절 (Network Throttling)**:
   * **Network** 탭 ➔ **Throttling** 드롭다운 선택 ➔ **Fast 3G** 또는 **Custom Profile (5Mbps / Latency 100ms)** 설정.
3. **테스트 진행**:
   * 대용량 영상 재생 시 타임라인 아래 **"실시간 버퍼"** 게이지가 실시간으로 차오르는지 확인.
   * 네트워크가 조여진 상태에서 **[⚡ 10초 안전 버퍼 충전]** 버튼을 눌러 버퍼 충전 HUD와 10초 도달 후 자동 재생 재개 동작 확인.
   * 타임라인 임의 위치로 Seek 시 딜레이 없이 즉시 재생 시작되는지 확인.
